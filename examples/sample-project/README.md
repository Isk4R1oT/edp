# Sample EDP project layout

This is a minimal example of what an EDP store looks like inside a project. It contains two active decisions used in the walkthrough in `../../EXAMPLE.md`.

## Layout

```
.edp/
├── config.json                 # selector policy + known tags
├── store.db                    # SQLite (NOT in this example — generated by SDK)
└── decisions/                  # human-readable markdown projection
    ├── DEC-0001.md
    └── DEC-0002.md
```

The `store.db` SQLite file is the authoritative store; the markdown files under `decisions/` are a read-only projection generated by the SDK for git review and human inspection. Editing the markdown files does not change the store — `edp record` and `edp supersede` are the only authoritative writers.

In this example the `store.db` is not present because the SDK does not exist yet; the markdown files alone illustrate the on-disk shape of decision records.
