## Context

- Codebase is migrating from SQLAlchemy 1.4 to 2.x.
- New code is being written alongside legacy sync code.
- We want a hard cut, not a hybrid, to avoid silent context-switching bugs and to simplify the eventual legacy removal.

## Decision

All new code uses SQLAlchemy 2.x patterns exclusively, with `AsyncSession` and async drivers (`asyncpg` for Postgres, `aiosqlite` for SQLite). No new sync sessions, no `scoped_session`. Legacy sync code is allowed to remain until each file is refactored, but no new sync session may be introduced in any new file.

## Evidence

- @session_log/step_2/user_message
- @artifacts/services/users.py:1-40

## Alternatives considered

1. **Hybrid sync + async per service.** REJECTED: invites accidental sync calls inside async handlers, locks the event loop, hard to detect in code review.
2. **Big-bang refactor of all legacy at once.** REJECTED: out of scope for current sprint, too much risk.

## Key constraints

- no sync sessions
- all new code uses AsyncSession
- async drivers only: asyncpg, aiosqlite

## Consequences

- Enables: cleaner refactor path, single mental model for new code
- Closes: any consideration of `Session()` / `scoped_session()` in new files
- Risk: developers used to sync API may write blocking calls inside async handlers. Mitigation: code review checklist + ruff rule for sync DB calls inside async funcs (TODO)
