## Context

- Legacy endpoints support both JSON and XML via content negotiation.
- XML support has not been used by any consumer in the analytics window (last 90 days).
- Maintaining the second serialiser path is dead weight for new endpoints.

## Decision

All new endpoints expose only JSON responses (`response_class=JSONResponse`). No XML serialisation in new code. Legacy XML endpoints remain until deprecation is announced separately.

## Evidence

- @session_log/step_4/user_message
- @artifacts/analytics/endpoint_usage_90d.csv

## Alternatives considered

1. **Continue dual-serialisation for parity.** REJECTED: no consumer signal, doubles surface to test and document.
2. **Deprecate all XML now.** REJECTED: too aggressive for current sprint, requires consumer comms.

## Key constraints

- no XML serialisation in new endpoints
- response_class=JSONResponse

## Consequences

- Enables: smaller code surface, simpler test matrix
- Closes: any new XML schema work
- Risk: an undocumented internal consumer breaks. Mitigation: search logs for XML accept headers in the last 30 days before merging endpoint changes that touch shared base classes.
